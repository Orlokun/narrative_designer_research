Architecture

How the pieces fit: a linear harvesting pipeline backed by a single SQLite database, with all outbound HTTP funnelled through one gatekeeper.

Canonical pipeline

The canonical step-by-step that defines the project. Steps 1–9 are implemented (with the threshold question noted below); more steps will be added as the design is finalised.

#StepTypeRole
1PropositorAgent · GemmaReads the heatmap (coverage matrix) and creates queries for the gaps.
2GatekeeperSoftware / classCalls all APIs, respecting their policies and document types, with the queries from the Propositor. Full source list: Sources & APIs.
3ArchiveroAgentReads metadata and the file to organise document type and store it.
4VerificatorAgent · GemmaReads the file and assesses how relevant it is for Cybersyn / Allende / Fernando Flores research.
5CleanerLogic (in Verificator)If the Verificator score is below the threshold (< 0.6 on the 0.0–1.0 scale), the file is dropped. Runs in every pipeline target right after the Verificator.
6MapperAgent · GemmaReads the document and establishes its position on the heatmap.
7Cast Manager RealAgentReads documents, extracts people mentioned (and who mentions them, when available), and adds each character to the database. Keeps a timeline of facts and data per character so the Propositor can later research that character.
8Cast Director RealAgentReads documents and the Cast Manager's hard data to extract more complex information: affective / familial relations, political affiliations, colleagues, enemies, etc.
9Document Curator RealAgent · GemmaReads each verified+mapped document and assigns utility flags — what it is especially good for (good-for lenses + quality) — into doc_flags, surfaced as reader filters.
10Location Manager RealAgent · GemmaReads documents and extracts the places where events happen — with descriptions, appreciations, events and hard data per location, GPS/architect from Wikidata, and location research missions fed back to the Propositor. Runs alongside the Cast Manager (independent stamp).
…More steps to follow — to be added as they are confirmed.
▶ Verificator threshold — decided & applied

Score scale is 0.0–1.0; the threshold is 0.6 (score < 0.6 → dropped by the Cleaner). The code default is min_score = 0.6, and verificator clean runs inside every pipeline target (pipeline, pipeline-loop, drain, drain-loop) right after verification.

Agents are CLI tools, not long-running services; only the Gatekeeper and the Admin dashboard stay up permanently. See Commands for how a full cycle is invoked (make pipeline).

▶ Entity-driven missions — built

The Propositor's mission queue is fed by two sources: matrix coverage gaps and new characters surfaced by the Cast Manager (research that person). Each cycle the Propositor polls the needs_research queue and mints kind='entity' missions; the Archivero runs them like any other mission but never writes their nominal cell to the coverage matrix. The mission mix is selectable at pipeline start: propositor --focus mixed|cells|characters — and make pipeline-characters runs a whole cycle focused on completing incomplete characters (entity missions only, least-complete first, then extract → enrich → analyze). The Location Manager feeds the queue the same way: kind='location' missions (architectural docs, plans, place history) mint in mixed mode via --location-limit, with documents.seed_location_id closing that loop. See Commands.

SQLite is the single source of truth

One database: data/archivo/archivo.sqlite. Three main tables — see Data Model for full columns:

TableWritten byRole
missionsPropositorGap-ranked + entity (character-research) search missions. Lifecycle pending → running → done | failed.
documentsArchivero (+ Verificator, Mapper stamps)All fetched documents, deduplicated by SHA-256.
coverageArchivero / MapperPer-cell coverage score for the 16×13×48 matrix (genre 0 = unclassified). Schema owned by lib/coverage.py.

The missions.json snapshot and documents.json export are derived views — never use them as input.

Mission failure logic (Archivero)

OutcomeCondition
DONEAt least one document found (new or duplicate SHA-256).
PENDING (reset)All fetch attempts failed at network level (timeout/5xx) — retried next cycle, not marked failed.
FAILEDSources reachable but returned no extractable content.

Source routing in Archivero

  • JSON API sources (_JSON_SOURCES): archive.org, frus, openalex, crossref, wikisource_es — each has a dedicated extractor in _JSON_EXTRACTORS.
  • HTML sources: bn_digital, web_serp — passed through trafilatura (80-char minimum applies only to HTML extractions).
  • _ERROR_PATTERNS rejects known bot-challenge / error pages before insertion.
  • frus queries archive.org with a FRUS+Chile+diplomatic prefix (US State Dept declassified docs); it reuses _archiveorg_extract.

Gatekeeper fronts all HTTP

Every outbound request goes through POST /fetch on port 8001. It enforces per-domain async locks, per-domain rate limits, a circuit breaker, and a 7-day disk cache. Full detail on the Gatekeeper page.
