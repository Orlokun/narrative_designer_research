Document Curator Real

Step 9 of the canonical pipeline (Ag-9). The Mapper answers what a document is about; the Curator answers what it is especially good for, tagging each verified, mapped document with utility flags so downstream views can pull a curated set.

What it does

For each verified + mapped document the Curator asks Gemma which utility flags apply, from a fixed vocabulary (lib/doc_flags.py) of two kinds:

  • good-for — the document is a strong input for a particular lens / future visualiser: military-logic, economic-planning, diplomacy, popular-life, ideology-rhetoric, science-technology.
  • quality — a judgement about the source itself: high-value, eyewitness.

The canonical example: "188. Memorandum for the Record" is a strong source for military logic — the Curator makes that legible and filterable instead of leaving it buried in the corpus.

Place in the flow

Runs after the Mapper (and alongside the Cast Manager / Cast Director, all of which read verified+mapped documents). Output is a curated tag layer surfaced as reader filters today, and an input to future visualisers.

Implementation

Lives in pipeline/doc_curator/__init__.py (class DocumentCurator, pure helpers, a main() CLI). The vocabulary is the pure module lib/doc_flags.py. Persists to the doc_flags table.

DecisionResolved as
Vocabulary as truthlib/doc_flags.py is the single source of truth for the flag slugs, names, kinds and descriptions — every consumer (Curator, reader, future visualisers) imports FLAGS rather than hard-coding slugs. Slugs are treated as a stable API (renaming one is a data migration).
SchemaA many-to-many doc_flags table — (doc_id, flag, confidence, rationale, assigned_by, assigned_at), UNIQUE(doc_id, flag) — plus a flags_curated_at stamp on documents (self-terminating, like the Cast Manager / Director).
LLM strategyPer document: each doc is read once (Gemma, think=False) against the flag menu, returning a short JSON list of {slug, confidence, rationale}. Curation is idempotent — a doc is re-flagged wholesale (old flags replaced) and capped at 5 flags so a "good-for-everything" doc is good for nothing.
Deterministic fallback--no-llm uses heuristic_flags — keyword frequency per flag (good-for flags only; quality flags are LLM judgements). Offline, fast, deterministic; stamped assigned_by='heuristic' vs. 'curator' for the LLM path.
Provenance & confidenceEvery flag carries a one-line rationale and a confidence (0–1). The reader shows the confidence and uses the rationale as the chip tooltip.

CLI

uv run doc-curator run [--batch 50] [--all] [--re-curate] [--no-llm]
uv run doc-curator status
uv run doc-curator clear [--apply]   # wipe all flags (dry-run by default)

Records a doc_curator stage against the active run_id. Make targets: make curate / curate-all / curate-status / curate-recurate. Reader filters live on the Archivero page (/api/documents/flags, ?flag=).
