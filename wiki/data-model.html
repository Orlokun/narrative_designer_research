Data Model

The SQLite schema (the single source of truth for data) and the Pydantic models that cross agent boundaries.

SQLite: data/archivo/archivo.sqlite

missions

Generated by the Propositor. Status lifecycle pending → running → done | failed. Network-only failures reset to pending (not failed) to allow retry. _cleanup_duplicates() runs at cycle start. Key columns: mission_id, category_id, month_iso, genre_id, queries, sources, status, priority, kind, character_id.

kind is 'gap' (coverage-matrix cell), 'entity' (character research; character_id set, id prefixed e-) or 'location' (place research; location_id set, id prefixed l-, duplicate cleanup keyed per location, newest wins). Gap missions carry genre_id (their matrix genre cell; NULL on legacy rows); entity missions carry a nominal cell that the Archivero never writes to the coverage table, and duplicate cleanup keys them by character_id instead of the cell (gap missions key by category+genre+month). All three columns are added to legacy databases by an idempotent migration in _ensure_missions_table().

documents

Written by the Archivero; deduplicated by SHA-256 (UNIQUE INDEX idx_doc_sha256). doc_id = first 16 hex chars of the sha256. Stamped later by the Verificator and Mapper:

The Cleaner (verificator clean) deletes rows where quality_score IS NOT NULL AND verified_at IS NULL — i.e. documents that were scored but failed the threshold. Unscored and verified rows are kept. See Verificator.

coverage — 3D (theme × genre × month)

Owned by lib/coverage.py (shared by Archivero and Mapper so the schema can't drift). Upserted when a mission is done / after mapping. coverage_score = min(1.0, docs_found / 5) (5 verified docs → 100% for a cell). Keyed by (category_id, genre_id, month_iso); genre_id 0 buckets pre-genre-axis / unclassifiable scores. ensure_coverage_table() migrates a legacy 2D table by moving its rows to genre 0. Read by the Admin heatmap. The genre registry itself (13 genres, plausibility priors, source affinities) lives in lib/genres.py — see Coverage Matrix.

pipeline_runs & pipeline_run_stages

Per-run tracking, written by lib/run_tracker.py. Each make pipeline run mints one run_id (exported as CYBERSYN_RUN_ID); the pipeline-run CLI brackets the run and each agent records its stage. Backs the Admin Performance & Results pages.

TableColumnsRole
pipeline_runsrun_id (PK), trigger, started_at, finished_at, statusOne row per full run. status = running / done / failed.
pipeline_run_stagesid, run_id, stage, started_at, finished_at, duration_s, counts (JSON)One row per agent/section per run — per-stage timing + counts (Performance page).

Stage recording no-ops when CYBERSYN_RUN_ID is unset, so standalone single-agent runs (e.g. make archivero) are unaffected. "Newly verified in run X" = documents WHERE run_id = X (Results page).

cast — characters, character_timeline, character_mentions & character_relations

Written by the Cast Manager (Step 7) from verified, mapped documents. character_id is a normalised slug of the name (the dedup key).

TableColumnsRole
characterscharacter_id (PK), name, aliases (JSON), biography, completeness_score, completeness_detail (JSON), mention_count, needs_research, research_attempts, last_research_at, run_id, birth_date, death_date, wikidata_id, wikipedia_url, wikidata_desc, wikidata_checked_at, wikidata_analyzed_at, wikipedia_analyzed_at, pol_economic, pol_social, pol_label, pol_source, pol_checked_at, first_seen_at, updated_atOne row per person. needs_research = 1 is the Propositor's entity-mission signal — cleared once the Propositor mints the character's entity mission, and re-set by the Cast Manager's refresh_research_flags when the character is still thin (completeness < 0.85), under the attempt cap and past the cooldown. research_attempts (bumped per minted mission) and last_research_at bound and pace that loop (should_research: max 5 attempts, 3-day cooldown). run_id is the run that first added them (Results page). birth_date/death_date (ISO year or date, nullable) bound the admin life-line chart — extracted by the LLM when a document states them, backfilled/upgraded to the most precise value, and carried to the survivor on a merge. wikidata_id/wikipedia_url/wikidata_desc are filled by cast-manager enrich (Wikidata lookup via the Gatekeeper); wikidata_checked_at stamps every character it processes so it never re-queries. wikidata_analyzed_at/wikipedia_analyzed_at stamp the cast-manager analyze step — mining claims/article into the profile; the strict metric only grants full external credit once set. completeness_detail persists the metric's per-component breakdown + active caps for the admin. pol_economic/pol_social (−1..1) place the character on a political compass (cast-manager politics, via Gemma; lib/politics.py); the Cast Director uses their distance to correct relation kinds.
character_timelineid, character_id, doc_id, date_iso, kind, description, speech_act, reported_by, confidence, created_at — UNIQUE(character_id, doc_id, description); restated facts across documents are collapsed by the Cast Manager's dedupe passPer-character dated facts (kind = role / event / affiliation / other / statement / rumor). speech_act (Searle/Flores enum) qualifies a statement; reported_by + a low confidence are the required context of a rumor. The UNIQUE key makes re-extraction idempotent.
character_mentionsid, character_id, doc_id, mentioned_by, created_at — UNIQUE(character_id, doc_id)Which documents mention a character, and (when stated) who mentions them.
character_relationsid (PK), source_character_id, target_character_id, kind, description, confidence, mention_count, provenance (JSON doc_ids), first_seen_at, updated_at — UNIQUE(source, target, kind)Written by the Cast Director (Step 8). Directed character→character relations (kind ∈ familia/aliado/colega/rival/enemigo/afiliacion/contraparte/superior/mentor/otro; symmetric kinds stored ordered). confidence = min(1, docs/3) rises with corroboration; provenance cites the documents that justify the relation.

completeness_score (0-1) is the strict metric: identity 0.15 + documentary base 0.20 (mentions/8) + external linking 0.25 (Wikidata/Wikipedia, analyzed > linked) + timeline richness 0.30 (volume/12 · kind-group diversity · month spread) + pipeline passage 0.10 — then hard-capped: no external analysis → ≤0.60, <3 of the 4 kind groups → ≤0.75, no completed entity mission → ≤0.80. Complete = ≥0.85. Full formula on the Cast Manager page; the breakdown is persisted in completeness_detail. The Cast Director (Step 8) reads these tables to build the relational layer.

locations — places, mentions & facts

Written by the Location Manager (Ag-4) from verified, mapped documents. location_id is a normalised slug of the name.

TableColumnsRole
locationslocation_id (PK), name, aliases (JSON), kind (building/factory/residence/city/region/street/office/other), description, latitude, longitude, character_id, completeness_score, completeness_detail (JSON), mention_count, needs_research, research_attempts, last_research_at, wikidata_id, wikipedia_url, wikidata_desc, wikidata_checked_at, wikidata_analyzed_at, wikipedia_analyzed_at, run_id, first_seen_at, updated_atOne row per place. character_id links a place tied to a person ("casa de Salvador Allende"). latitude/longitude come from Wikidata P625 via location-manager analyze. The research columns drive the same bounded loop as characters (needs_research → Propositor kind='location' missions; < 0.85, 5 attempts, 3-day cooldown).
location_factsid, location_id, doc_id, date_iso, kind, detail, reported_by, created_at — UNIQUE(location_id, doc_id, detail)Per-place facts: description (objective), appreciation (subjective, with reported_by), event, data (address, capacity, architect, inception, trivia).
location_mentionsid, location_id, doc_id, created_at — UNIQUE(location_id, doc_id)Which documents mention a place.
location_imagesid, location_id, filename, url, page_url, caption, source, created_at — UNIQUE(location_id, filename)The place's image gallery, harvested by location-manager analyze: Wikidata P18 images (served via Commons Special:FilePath thumbnails) and the Wikipedia article's lead image. filename is the normalised dedup key, so the same file arriving from both sources stores once; page_url is the Commons File: page (licence + attribution).

completeness_score (0-1) = documentary base 0.25 (mentions/4) + facts 0.30 (facts/6) + external linking 0.30 (analyzed > linked) + coordinates 0.15; hard gate: no external analysis → ≤0.60; complete = ≥0.85. Formula on the Location Manager page.

doc_flags — document utility flags

Written by the Document Curator (Step 9, Ag-9). Many-to-many between documents and the fixed utility-flag vocabulary (lib/doc_flags.py): what each document is especially good for, distinct from the theme/genre the Mapper assigns. Surfaced as reader filters.

TableColumns / keysNotes
doc_flagsid (PK), doc_id, flag (slug), confidence, rationale, assigned_by, assigned_at — UNIQUE(doc_id, flag); indexed on flag and doc_idFlag slugs come from lib/doc_flags.py — good-for lenses (military-logic, economic-planning, diplomacy, popular-life, ideology-rhetoric, science-technology) and quality judgements (high-value, eyewitness). assigned_by = 'curator' (Gemma) or 'heuristic' (--no-llm keyword pass). A document is re-flagged wholesale (idempotent), capped at 5 flags.

Pydantic schemas (lib/schemas.py)

Used at agent boundaries instead of raw dicts. Grouped by purpose:

Archive & missions

  • Document — canonical archive entry (doc_id, title, text, lang, date_iso, authors, places, source_kind, source_id, provenance, rights, sha256, ingested_at).
  • SourceKind — enum: PRESS, GOVERNMENT, ACADEMIC, ARCHIVE, INTERVIEW, CORRESPONDENCE, OTHER.
  • Mission, MissionKind (GAP | ENTITY), FetchRequest, FetchResponse, DomainStatus — mission + Gatekeeper API primitives. Entity missions set Mission.kind = ENTITY and Mission.character_id.

Cast (output of Cast Manager, agent 7)

  • Character — person extracted from the archive (character_id, name, aliases, biography, completeness_score, completeness_detail, mention_count, timeline, needs_research, run_id).
  • CharacterFact — one dated timeline fact (kind, description, date_iso, doc_id, speech_act, reported_by, confidence).
  • CharacterMention — a (character_id, doc_id, mentioned_by) link. Mirrors the cast tables.

Locations (output of Location Manager, Ag-4)

  • Location — place extracted from the archive (location_id, name, aliases, kind, description, latitude, longitude, character_id, completeness_score, completeness_detail, mention_count, facts, needs_research, run_id).
  • LocationFact — one fact about a place (kind: description / appreciation / event / data; detail, date_iso, doc_id, reported_by). Mirrors the location tables.

Dialogue & speech acts (Searle / Flores–Winograd)

  • SpeechAct — ASSERTIVE, DIRECTIVE, COMMISSIVE, EXPRESSIVE, DECLARATIVE.
  • CommitmentAction — REQUEST, OFFER, PROMISE, COUNTER_OFFER, DECLINE, CANCEL, DECLARE_COMPLETE, DECLARE_SATISFIED, WITHDRAW.
  • CommitmentStage — PREPARATION, NEGOTIATION, PERFORMANCE, ACCEPTANCE, CLOSED_SATISFIED, CLOSED_BROKEN.
  • Utterance, Commitment, DialogueExample (SFT/QLoRA training example).

Narrative & game

  • NPCPersona — character spec (biography, speech_style, political_position, relationships, rag_anchors, portrait_asset).
  • NarrativeNode, NarrativeBranch — branching story graph.
  • Scenario, Indicator, MetricSpec, GameRules, EventTemplate — Operations-Room metrics and scenario definitions.

The richness here describes the intended end state (NPC dialogue, scenarios, metrics) — most consuming agents are still Stub or Rebuild. See the Roadmap.
