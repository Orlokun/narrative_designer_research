Gatekeeper Real

A FastAPI microservice (port 8001) that every outbound HTTP request passes through. It is one of only two long-running services (with the Admin dashboard).

Entry point: research_engine/gatekeeper/app.py → main() · also domain_state.py, rate_limits.yaml · CLI: make gatekeeper

Everything goes through POST /fetch

The Gatekeeper enforces, per request:

MechanismBehaviour
Per-domain async locksSerialises concurrent requests to the same domain.
Rate limitingMinimum interval per domain from rate_limits.yaml. DuckDuckGo at 0.05 rps (it actively blocks bots). The default entry (0.1 rps) applies to any unlisted domain.
Circuit breaker3 consecutive failures (5xx / network) → domain cooldown (30 min default).
429 handlingHonors the source's Retry-After header (a short hint wins even mid-escalation); otherwise escalating backoff — 60s doubled per consecutive 429, capped at 30 min. The escalation decays with time served (one step per elapsed base period) and a success resets it — so a domain that waits out its penalties recovers instead of pinning at the cap. Repeat offenders still show growing cooldowns in the admin: deliberate etiquette, not a bug.
API keysOptional per-source keys from .env via lib.config.settings — e.g. SEMANTIC_SCHOLAR_API_KEY (free) sends x-api-key and moves us off Semantic Scholar's shared unauthenticated pool, which 429s under global load regardless of our own politeness.
Disk cache7-day TTL; cached responses cost zero rate-limit tokens.

Health & observability

The Admin dashboard reads Gatekeeper state via /health/gatekeeper/status (per-domain state) and /health/gatekeeper/log (recent fetch log). Rate limits live in research_engine/gatekeeper/rate_limits.yaml — see the full Sources & APIs roster for every domain's policy, format and tier.

Configuration

Host/port come from lib.config.settings (gatekeeper_host/gatekeeper_port) — never hard-coded. Tested in tests/test_gatekeeper.py (cache hits, circuit breaker, 429 handling, PDF binary detection, health endpoint).
