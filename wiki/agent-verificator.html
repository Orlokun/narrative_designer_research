Verificator Ag-2 Real

Quality-scores each fetched document and gates which ones are kept. Also hosts the Cleaner, which prunes documents that failed verification.

Entry point: pipeline/verificator/__init__.py → main() · CLI: verificator run / status / clean

Scoring: score_document(text, title) → float [0.0–1.0]

A pure function (tested in tests/test_verificator.py). Weighted signals:

ComponentMaxSignal
Length0.20min(text_len / 1000, 1) × 0.20
Chilean keywords0.45unique keyword hits × 0.08, capped
Period years (1969–1973)0.25year hits × 0.08, capped
Spanish language0.10≥ 3 Spanish function words present

Hard rejects (score = 0.0): texts shorter than MIN_DOCUMENT_LENGTH (100 chars) or matching _REJECT_PATTERNS.

Threshold (canonical): 0.6. A document passes if its score is ≥ 0.6 and gets a verified_at timestamp; below 0.6 the Cleaner drops it. Note: the current code still defaults to min_score = 0.6 is the code default since June 2026, and the Cleaner runs automatically after verification in every pipeline target.

The Cleaner (_clean_rejected)

Invoked via verificator clean / make cleaner. It runs:

DELETE FROM documents WHERE quality_score IS NOT NULL AND verified_at IS NULL
  • Removes documents that failed verification (scored, but below threshold).
  • Keeps unscored rows (quality_score IS NULL) — retried next run.
  • Keeps verified rows (verified_at IS NOT NULL).
  • make cleaner-dry-run previews deletions without removing anything.

Tested in tests/test_cleaner.py.

Common invocations

make verificator          # run --batch 200
make verify-queue         # loop until the queue is drained
make cleaner-dry-run      # preview rejections
uv run verificator status
