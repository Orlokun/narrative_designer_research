The reusable platform

How one historical moment becomes a research project, how a project drives every agent, and how the game Director consults the result. This page is the entry point for anyone who wants to document a different moment than Project Cybersyn.

▶ Origin

This repository is a translation of the cybersyn-backend research engine into a general tool. The Cybersyn engine itself was left untouched; here its hardcoded historical knowledge (themes, dates, vocabulary, prompts, source routing) was lifted into a declarative project spec, and three new pieces were added around the pipeline: the Grid Proposer, the Source Scout and the Knowledge API for the Director. Project Cybersyn ships as the reference project (projects/cybersyn/project.yaml) and the pipeline behaves identically under it.

  1. Propose — uv run grid-proposer propose --moment "…" --start YYYY-MM --end YYYY-MM --region X --language xx --slug name writes projects/<slug>/project.yaml. Use --no-llm for a generic skeleton to fill by hand.
  2. Edit the YAML. It is meant to be read and corrected by a historian; nothing in it is hidden.
  3. Scout — uv run source-scout run --project name --apply (Gatekeeper running) probes the applicable connectors and writes the four source tiers.
  4. Activate — RESEARCH_PROJECT=name in .env. Every agent now reads that grid.
  5. Run the normal cycles (make pipeline, make pipeline-characters) — see Commands.
  6. Consult — the game Director calls KnowledgeBase.context(...) with the player's situation.

The project spec — lib/project.py

A ResearchProject (Pydantic, extra="forbid") loaded from YAML. It is the single place where a moment is described; agents import project() (cached) and derive their module constants from it at import time, so their code reads as before.

Selection: settings.research_project (env RESEARCH_PROJECT) — a slug under projects/ or a path to a YAML. Validation is strict: unknown keys, duplicate theme ids, a critical month outside the period or a missing tier all fail at load time.

What is still Cybersyn-shaped: the genre axis (lib/genres.py) keeps its 13 genres and Spanish search terms; its per-theme plausibility overrides apply only when the active project is Cybersyn (overrides_active()), other projects use each genre's default prior. Per-project genre vocabulary is the next generalisation step (Roadmap).

Grid Proposer (RE-0) — research_engine/grid_proposer/

Real Turns a MomentBrief (moment, period, region, language, slug, number of themes) into a complete ResearchProject. The LLM (LLMClient, director model) is asked for one JSON object — themes with weights and period search terms, critical months, seeds, relevance topics and zero-score rules, era labels, vocabulary hints, query suffixes. Pure functions then do the trustworthy part: normalise_themes (renumber, dedup, clamp weights, derive tiers from weight), normalise_critical_months (inside the period, sorted), normalise_seeds, and build_project fills everything else deterministically (source tiers from the catalogue, entity defaults, prompt personas, score scale). A non-JSON or failing LLM falls back to skeleton_proposal — a generic 12-theme grid with no historical claims — which is also what --no-llm writes. write() refuses to overwrite an existing spec without --force.

CommandDoes
grid-proposer propose --moment … --start … --end … --region … [--language en] [--slug] [--title] [--themes 12] [--no-llm] [--out PATH] [--force]Draft and write the spec; prints a summary and the next step.
grid-proposer show <slug|path>Print a spec summary (themes, critical months, seeds, critical-tier sources).

Source Scout (RE-0b) — research_engine/source_scout/ + lib/sources.py

Real "Which APIs actually have material for this moment?" The connector catalogue (lib/sources.py) describes every connector the Archivero can call — kind, access style, languages, regions, coverage years. applicable_connectors(project) filters it: the Chile Declassification Project, FRUS vol. XXI and the Marxists Allende archive drop out of a Weimar project; wikipedia/wikisource are language-parametric and resolve to wikipedia_de/wikisource_de (the Archivero builds their URLs for any language code). The Scout then sends a few probe queries per connector (from the heaviest themes' search terms plus region + critical year) through the Gatekeeper, runs the Archivero's own extractors over the replies and counts hits. recommend_tiers ranks reachable connectors by yield into the four tiers (web search always last and only in critica); --apply writes them (and the entity sources) back into the YAML.

CommandDoes
source-scout run --project <slug|path> [--probes 2] [--apply] [--gatekeeper URL]Probe, print the report (status · hits · rate · note per connector; exclusions with reasons; recommended tiers). Exit 1 when nothing is reachable (Gatekeeper down).
source-scout catalogue [--project …]List every connector; with a project, which ones apply.

Adding a connector still has three halves (Sources & APIs) — and now a fourth: a Connector entry in the catalogue so the Scout knows when to propose it.

LLM providers — lib/llm.py

The agents call LLMClient() and catch LLMError; the backend is chosen by LLM_PROVIDER:

ProviderBackendConfig
ollama (default)lib.ollama.OllamaClient — a local Ollama server (the original setup).OLLAMA_HOST, OLLAMA_MODEL_NPC, OLLAMA_MODEL_DIRECTOR
geminiGeminiClient — Google AI Studio's Gemini API, which serves the open Gemma models on a free tier. No local GPU needed. Requests are paced to GEMINI_RPM and retried on 429/5xx with backoff; the model name the agents pass (an Ollama tag) is mapped onto GEMINI_MODEL, and list_models() reports the Ollama tags as aliases so the agents' presence checks keep passing.GEMINI_API_KEY, GEMINI_MODEL (default gemma-3-27b-it), GEMINI_RPM (default 25)

Both expose the same verbs (generate, chat, list_models); tests stub LLMClient per module and never touch the network. Gemini calls go direct, not through the Gatekeeper (it is not a harvest source).

Knowledge API for the Director — lib/knowledge.py

Real The read path from the archive to the game. A DirectorQuery describes the player's situation — month_iso (± month_window), theme_ids, genre_ids, character_names, location_names, flags (Document Curator lenses), free keywords, limit. KnowledgeBase.context(query) returns a DirectorContext:

  • documents — verified (quality_score ≥ 0.6) and mapped docs, filtered by theme/month/genre/flags/keywords and ranked by score_document (primary theme ×2, exact month, quality, lens and keyword matches), each with a keyword-centred snippet;
  • characters — dossiers resolved by name or alias: biography, political label, the first dated timeline facts (speech acts and hearsay included), relations with their counterparts;
  • locations — place dossiers with coordinates and facts.

as_prompt() renders the bundle as a plain-text evidence block, truncated to a character budget, ready to paste into the Director's prompt; the whole context round-trips through JSON for logging and replay. The API tolerates a partial archive (missing tables → empty sections) and is project-agnostic (theme names come from the active spec). Wiring it into the runtime Director's node loop is the next step (Roadmap).
