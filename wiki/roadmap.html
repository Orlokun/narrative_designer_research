Rebuild Roadmap

What was lost, what to rebuild, and the path back to deployment. This page is the work queue for the rebuild.

▶ Situation

~4 weeks of work (around 6 new agents + heavy Admin enhancements, just before a planned web deployment) were lost when the PC was reformatted and the repo re-cloned from GitHub — that work had never been pushed. Recovery (git reflog/dangling objects, VS Code local history, Windows copy, off-machine backups) came up empty.

Baseline: HEAD c9b4c3a (2026-04-26). Goal: restore to the pre-loss state and deploy to the web.

▶ Architecture being canonicalized — steps 1–8 implemented

The canonical pipeline is being shared step-by-step (see Canonical pipeline). Steps 1–9 are now implemented (Step 7 Cast Manager + Step 8 Cast Director + Step 9 Document Curator). More steps will follow as the architecture is finalised.

Character research loop — closed & iterative Done

Characters now seed their own research and the harvest feeds back to them, so a person's record grows robust over successive cycles instead of one shot.

  • Seed attribution (Archivero + Cast Manager): a doc harvested by a character's entity mission carries documents.seed_character_id; the Cast Manager force-attributes it to that seed (a mention) even if the LLM does not re-extract the name — the loop closes deterministically.
  • Iterative & bounded: refresh_research_flags re-flags a still-thin character (should_research: completeness < 0.85 under the strict metric, ≤ 5 attempts, 3-day cooldown) after each cycle; research_attempts / last_research_at bound and pace it. In-flight-only suppression + newest-wins entity dedup let a fresh attempt supersede an earlier done mission.
  • Richer seeds: entity_queries now draws on the character's aliases and top affiliation (e.g. "Donald Kendall" president of Pepsi-Cola).
  • Strict completeness metric (done): weighted components + hard gates (no Wikidata/Wikipedia analysis → ≤0.60; <3 of 4 timeline kind groups → ≤0.75; no completed entity mission → ≤0.80); breakdown persisted in completeness_detail. See Cast Manager.
  • cast-manager analyze (done): Wikidata claims + the Wikipedia article are mined into the profile/timeline (facts, vital dates, biography), stamping the *_analyzed_at gates; implausible homonym links (birth > 1973) are undone. See Cast Manager.
  • statement/rumor extraction (done): the extraction prompt captures quotes (with their speech act) and attributed hearsay; unattributed rumors are rejected. With analyze + article bios in place, every lever a character needs to reach ≥0.85 under the strict metric now exists — backfill the existing corpus with cast-manager run --re-extract.
  • make pipeline-characters (done): a whole cycle focused on completing incomplete characters — propositor --focus characters mints entity missions only (least-complete first), the standard chain harvests, and the Cast Manager extracts → enriches → analyzes → re-scores. Trigger characters in run tracking; the normal make pipeline now also advances enrich/analyze in small bounded batches.
  • Calibration tooling (done): cast-manager score / make cast-score bulk-recomputes all completeness under the current constants (run it after deploying a metric change); the admin cast sidebar shows the score histogram + per-gate counts, and each detail its component breakdown — the evidence base for tuning weights/targets against the real corpus.
  • Location Manager (Ag-4) (done): the spatial twin of the cast loop — places where events happen, with descriptions/appreciations/events/data, Wikidata GPS + architect + Wikipedia trivia via location-manager enrich/analyze, and kind='location' Propositor missions (architectural docs, plans, place history) closed by documents.seed_location_id. The admin Locations page (/locations: SVG coordinate map + list + detail) is done. Follow-ups: locations.geojson export, Nominatim fallback — see Location Manager.

Improvement backlog — user feedback (June 2026)

Improvements raised after the first end-to-end cast runs. All six items Done — item 4 (document utility flags) shipped July 2026 as the Document Curator (Step 9).

1 · Cast Manager extraction recall Done

The Cast Manager misses named people in documents it does process. Confirmed on "188. Memorandum for the Record" (mapped to EEUU, cast_extracted): Richard Helms was captured, but Agustín Edwards and Donald Kendall (president of Pepsi-Cola) were not — so this is an LLM recall gap, not a coverage gap.

  • Sharpen the people-extraction prompt to enumerate every named person, including foreign businessmen, and to carry their role/affiliation as a fact ("Donald Kendall — president of Pepsi-Cola").
  • Consider a larger model for this step, or a deterministic NER second pass to backstop Gemma's misses.
  • Add a --re-extract mode that re-mines already-processed documents (the current cast_extracted_at stamp makes runs skip them).

Shipped (July 2026): sharpened exhaustive prompt; a high-precision cued backstop (cued_person_names — honorific-before or role-after cues, organisation/place stoplist) that unions names the LLM missed on the LLM path; and cast-manager run --re-extract / make cast-remine. Remaining: run a full re-mine once Ollama is back up; a larger model or a proper NER (spaCy PERSON) pass is still an option for further recall.

2 · Wikidata & Wikipedia links per character Done

Each character should link out to its Wikidata entity and Wikipedia page for grounding and disambiguation. Store wikidata_id / wikipedia_url on characters (resolved by name lookup against Wikidata — ties into the deferred Wikidata-SPARQL connector) and surface them as links on the /cast-manager detail. Also a natural source for birth/death dates and the political position below.

Shipped (July 2026): characters gained wikidata_id / wikipedia_url / wikidata_desc / wikidata_checked_at; cast-manager enrich resolves them via the Wikidata API through the Gatekeeper (Spanish Wikipedia preferred, idempotent); the /cast-manager detail shows the external links + the Wikidata description. Note: the running Gatekeeper must be restarted once to pick up the new www.wikidata.org rate limit, else enrichment falls back to the slow default.

3 · Political compass per character → relation semantics Done

Give each character a 2-axis political position — left ↔ right and liberal ↔ authoritarian — and let it inform the Cast Director. Today opposed figures can be mislabelled: Kissinger and Allende are not afiliados — they are counterparts, even adversaries.

  • Add a political-position field per character (LLM-inferred + corroborated, or from Wikidata), shown on the cast detail (a small compass).
  • Add a contraparte (counterpart) relation kind, and use the compass as a sanity check: two far-apart positions should not yield afiliacion.
  • Feed the position into the Cast Director prompt so the relation kind reflects ideological distance, not just co-occurrence.

Shipped (July 2026): a pure lib/politics.py (2-axis compass — economic left↔right, social libertarian↔authoritarian; distance, quadrant labels, refine_relation_kind). characters gains pol_economic/pol_social/pol_label/…; cast-manager politics places each character via Gemma. The Cast Director adds a contraparte kind and, on upsert, downgrades a claimed afiliacion between ideologically distant figures to contraparte (Kissinger↔Allende); its prompt now forbids "political" for opponents. The /cast-manager detail shows a small compass; the graph colours contraparte. This also closes item 5's extraction-precision half.

4 · Document utility flags Done

Some documents are especially good inputs for a particular visualiser — e.g. "188. Memorandum for the Record" is a strong source for military logic. Let documents carry utility flags / tags (e.g. good-for: military-logic, high-value) so a downstream view can pull a curated set.

Shipped (July 2026): a dedicated curation step — the Document Curator (Step 9, Ag-9, pipeline/doc_curator/). A pure vocabulary registry lib/doc_flags.py (six good-for lenses — military-logic, economic-planning, diplomacy, popular-life, ideology-rhetoric, science-technology — plus two quality flags — high-value, eyewitness). A many-to-many doc_flags table with confidence + rationale + provenance; flags_curated_at makes runs self-terminating. Gemma assigns the flags per document (--no-llm keyword heuristic as a deterministic fallback); doc-curator run/status/clear + make curate*. Surfaced in the reader as flag chips on each document and a utility filter (/api/documents/flags, ?flag=). Remaining: feed the flags into the future visualisers as they land.

5 · Cast Director relation clarity & precision UI done

The relations on the /cast-director network are not legible enough — the user wants more detail and precision.

  • UI: directional arrowheads on directed edges, an edge tooltip/panel showing the justifying description + provenance documents, kind/confidence filters, and a clearer label layout than the current force graph.
  • Extraction precision: tighten the relation taxonomy (see item 3) so kinds are correct, and raise the confidence bar for what is drawn by default.

Shipped (July 2026, UI): directional arrowheads on directed edges; an edge hover label (native tooltip naming both characters, the relation kind, confidence and its description) and a click-through detail panel (both characters linked, description, confidence, provenance document links); kind filter chips and a confidence-threshold slider; edge width + opacity scaled by confidence; /cast/graph edges now carry description, provenance and directedness. Remaining: the extraction-precision half (correct kinds, e.g. Kissinger↔Allende) lands with item 3 (political compass).

6 · Deterministic cast validity filter Done

Noisy extraction (especially the --no-llm heuristic) created nonsensical characters — "El", "October", "Presidente", "Classification". Shipped (July 2026): is_plausible_person_name() — rejects names that are entirely boilerplate, bare titles, months, organisations or function words, while keeping real people (surname-only "Lanusse", title-prefixed "General Carlos Prats"). It gates extraction (prevention) and backs cast-manager clean (dry-run by default, --apply deletes + cascades). Chosen over an LLM verifier — deterministic, fast, free. Applied to the live DB: removed 13 garbage characters.

Hardened (July 2026, "Banco Edwards" regression): the bank passed the filter (only "banco" is an org token) and became a character; its single-token alias "Edwards" then let the merge pass absorb Agustín Edwards (the person, from doc "89. Memorandum for the Record") into the bank. Two fixes: a name opening with an institution designator (_ORG_DESIGNATOR_STARTS — banco, radio, diario, universidad…) is never a person; and coreference (resolve_character_key) only lets person-shaped forms anchor a match, so an org form or alias can never bridge a person into it. Live DB repaired: Agustín Edwards split out as his own character (mentions + personal facts, needs_research=1); the bank deleted via clean --apply.

Matrix redesign — genre axis Done

The research matrix became 3D in June 2026: 16 themes × 13 genres × 48 months (see Coverage Matrix). The Y axis keeps the themes; the new X axis tracks genre / document type (discurso, carta y telex, cable diplomático, documento oficial, transcripción, prensa informativa, prensa de opinión, informe técnico, académico, testimonio, poesía y canción, narrativa y teatro, propaganda); months remain as the third axis + critical-month boosts. Built across the stack: lib/genres.py (registry + plausibility priors), lib/coverage.py (shared 3D table), Mapper genre classification, Propositor 3D ranking with genre-routed sources, Admin theme×genre heatmap.

  • Follow-up: re-map the existing corpus so it gains genres — make remap-all (old docs sit in genre 0 until then).
  • Follow-up: curate the plausibility priors in lib/genres.py as the corpus grows.
  • Follow-up: when the Cambridge key-gated APIs land (ProQuest, Gale, JSTOR, HathiTrust, BCN…), add each to the per-genre source lists.

Admin page — Cast Manager Done

The admin view over the Cast Manager's character data — built as designed below (admin/routers/cast.py + admin/static/cast-manager.html, served at /cast-manager).

  • Left sidebar — character list:
    • One row per character, each showing an information-completeness score (0–1) (how much is known about that character).
    • A search bar to find characters.
    • Rows are clickable — selecting one loads its detail in the central section.
  • Central section — selected character detail:
    • A timeline of the character's roles/positions and key events — personal, professional and social.
    • A biographical summary of no more than one paragraph.
    • The list of documents in which the character is mentioned.

Admin page — Cast Director Done

The admin view over the Cast Director's relational layer.

  • A character relationship map — friendships, collaborators, counterparts, enemies, family, etc.
  • The relationship map is rendered as a network / graph.
  • Who mentions the character — the people who mention them (the speakers/sources), not the documents.
  • Associated institutions or groups.

Open architectural questions

  • Verificator threshold — done. Scale is 0.0–1.0, threshold 0.6 (< 0.6 → dropped). Default raised from 0.3 to 0.6 and verificator clean now runs inside every pipeline target right after verification (June 2026).
  • Entity-driven missions — done. The Propositor now polls fetch_characters_needing_research() each cycle and mints kind='entity' missions (capped by --entity-limit), so its queue is fed by both matrix gaps and new characters. Entity missions never touch the coverage matrix.
