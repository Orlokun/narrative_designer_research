Cast Manager Real

Step 7 of the canonical pipeline. Reads documents, extracts the people mentioned in them, and maintains a timeline of facts per character. Its output is what makes the Propositor's missions entity-driven as well as gap-driven.

What it does

  • Reads each verified document and extracts the people mentioned.
  • When the text supports it, records who mentions them (the source and the speaker).
  • Adds each new character to the database with a per-character timeline of facts and data drawn from the documents.
  • Surfaces newly-discovered characters back to the Propositor so it can generate entity-driven missions (research that person).
  • Closes the research loop: a document harvested by a character's entity mission carries its seed_character_id, and the Cast Manager force-attributes that document to the seed (a mention tagged entity-mission) even if the LLM does not re-extract the seed's name — so the character always gains evidence from research done on its behalf. No-op if the seed was absorbed by a merge.
  • Owns the research lifecycle: at the end of every cycle refresh_research_flags re-evaluates each character against the freshly harvested evidence — a still-thin character (should_research: completeness < 0.85, under 5 attempts, past a 3-day cooldown) is re-flagged needs_research for another attempt; a complete or exhausted one rests. This turns one-shot entity missions into a bounded, iterative loop.

Place in the flow

Runs after the Mapper: only verified, mapped documents are mined for cast information (it reads docs where verified_at and mapped_category_id are set but cast_extracted_at is NULL, and stamps each as it goes — so the run is self-terminating and idempotent). Output feeds the Cast Director (Step 8), which uses these hard facts plus the documents to extract more complex relationships.

Implementation

Lives in pipeline/cast_manager/__init__.py (class CastManager, pure functions, a main() CLI). The persisted entities are the Pydantic Character, CharacterFact and CharacterMention models in lib/schemas.py.

DecisionResolved as
SchemaThree tables — characters, character_timeline, character_mentions — plus a cast_extracted_at column on documents. See Data Model → cast.
ExtractionLLM-driven (Gemma, ollama_model_npc) via chat(), returning JSON people + facts. A --no-llm heuristic (capitalised-name runs, no facts) gives a deterministic offline fallback. Tests mock the Ollama client; the suite is fully offline.
Recall (backlog #1)The LLM misses named people even in documents it processes (confirmed: Agustín Edwards, Donald Kendall). Three-part fix: (1) a sharpened, exhaustive prompt that demands foreign businessmen/officials and records their role/affiliation; (2) a high-precision cued backstop (cued_person_names) that recovers names anchored by an honorific ("Mr. Donald Kendall") or a following role ("Agustín Edwards, publisher of El Mercurio"), filtered against an organisation/place stoplist so boilerplate is not captured; (3) a --re-extract mode to re-mine the existing corpus; and (4) chunked extraction — long documents are split into overlapping chunks (chunk_text, ~4000 chars, 250 overlap) mined one by one and the people unioned (merge_extracted_people), instead of a single arbitrary text[:N] cut that hid everyone named later in the file (the 15 kB "89. Memorandum for the Record" names attendees far past any fixed cut). Applies to the LLM path — --no-llm stays the rough capitalised-run fallback and should not be used to re-mine real data.
External grounding (backlog #2)Wikidata + Wikipedia links. cast-manager enrich resolves each character's name against the Wikidata API (wbsearchentities → wbgetentities sitelinks, Spanish Wikipedia preferred), routed through the Gatekeeper like every outbound request. Stores wikidata_id, wikipedia_url and the Wikidata wikidata_desc (shown on the cast detail as external links + a grounding hint). wikidata_checked_at makes it idempotent and self-terminating; the pure parsers are offline-tested. Also a natural future source of birth/death dates and the political compass (item 3).
External analysis (F1)Linked → analyzed. cast-manager analyze mines what enrich linked, via the Gatekeeper. Wikidata (no LLM): wbgetentities claims — P39 positions (with P580 start dates), P102 party, P106 occupation — become timeline facts (labels resolved es→en in one batched call); P569/P570 fill or precision-upgrade birth_date/death_date; a birth after 1973 (wikidata_identity_plausible) means a homonym and de-links the character (keeping wikidata_checked_at so enrich doesn't re-link it). Wikipedia (Gemma): the article's plain-text extract → parse_analysis_response → a one-paragraph biography (only when none exists) + dated facts. Each side stamps wikidata_analyzed_at / wikipedia_analyzed_at — the strict metric's external gates — and recomputes completeness. Fetch/LLM failures leave no stamp (retried next run); stamped rows are never re-queried, so runs are idempotent and self-terminating.
Statements & rumors (F2)Narrative extraction. The extraction prompt also captures what a person said (kind='statement', qualified by its Searle/Flores speech_act: assertive / directive / commissive / expressive / declarative) and hearsay about them (kind='rumor'). Hard rules in _clean_fact: an unattributed rumor is rejected outright (reported_by is mandatory), and a rumor without an explicit confidence defaults to a low 0.3. Narrative kinds never dedupe against the information kinds (_fact_kinds_compatible excludes them from the "other" wildcard), so a quote is never collapsed into a profile fact. Backfill over already-mined documents: cast-manager run --re-extract. The admin timeline renders statements as «quotes» with their act and rumors dimmed with "— según reported_by". These two kinds complete the four narrative groups the completeness diversity gate requires.
Validity filter (backlog #6)Deterministic, no LLM. is_plausible_person_name() rejects names that are entirely boilerplate, bare titles, months, organisations/places or function words, or that open with an institution designator ("Banco Edwards", "Radio Magallanes" — _ORG_DESIGNATOR_STARTS) — while keeping real people, including surname-only ("Lanusse") and title-prefixed ("General Carlos Prats") forms. It gates extraction (never stores garbage, LLM or heuristic alike) and backs cast-manager clean (dry-run by default; --apply deletes the implausible characters and cascades to mentions/facts/relations). Chosen over an LLM verifier — the garbage is obvious and a deterministic filter is faster and free.
Propositor signalPolled query — wired. New characters carry needs_research = 1; fetch_characters_needing_research() exposes that queue. The Propositor consumes it every cycle, minting kind='entity' missions and clearing the flag.
De-dup / coreferenceTwo layers. (1) character_key() slugifies exact forms. (2) resolve_character_key() unifies surface forms of the same person: name extensions match as ordered token subsequences with initials ("Salvador Allende" ↔ "Salvador Allende Gossens", "Henry A. Kissinger" ↔ "Henry Kissinger"), and surname-only mentions ("Allende", "Kissinger") match only when exactly ONE character carries that surname — ambiguity (Salvador vs Beatriz Allende) never merges. The fullest form becomes the canonical name; the rest accrue in aliases. A self-healing merge pass (merge_duplicate_characters(), cluster-level union-find with the same rules) runs at the end of every cycle and via cast-manager merge, re-pointing mentions/facts/entity missions to the survivor. Only person-shaped forms anchor a match (_looks_like_person): an organisation form or alias ("Banco Edwards") can never bridge a person into that character — the regression that once absorbed Agustín Edwards into the bank. Follow-up: strip honorifics ("Senator Jarpa", "Ambassador Korry") so the canonical name is the bare person.
Life dates & timeline chartEach character carries optional birth_date / death_date (LLM-extracted when a document states them; the most precise value wins and survives merges). The admin /cast-manager page renders an SVG life-line spanning birth→death (falling back to the dated-fact range), with the 1970–1973 Cybersyn period always highlighted and a lollipop marker per dated fact (coloured by kind). The span maths are pure, testable helpers in admin/routers/cast.py (_year_fraction, _timeline_span) — tolerant of corpus quirks ("1970-1973", "1970-00").
Timeline fact dedupThe same fact restated across documents ("President of Chile" / "Presidente de la República" / "asumió la presidencia") collapses into one row. facts_are_duplicates() compares content-token signatures (stopwords removed, bilingual es↔en canonicalisation: president/presidencia/presidential → presidente, etc.) with a ≥0.8 containment test; "other" acts as a kind wildcard (the LLM labels the same fact inconsistently). Two layers: insert-time skip (a restatement's date backfills an undated existing fact) and the dedupe_timeline_facts() pass — greedy clustering per (character, kind), survivor = richest description + earliest date — which runs after character merging in every cycle and in cast-manager merge.
Completeness score (strict)compute_completeness() takes a CompletenessInputs and returns a CompletenessResult (score + breakdown, persisted as completeness_detail JSON). Weighted components: identity 0.15 (⅓ bio + ⅓ a role fact + ⅓ vital dates) · documentary base 0.20 (mentions / 8) · external linking 0.25 (Wikidata 0.125 + Wikipedia 0.125; linked-but-not-analyzed earns only 0.06 each) · timeline richness 0.30 (0.5·facts/12 + 0.35·kind-group diversity + 0.15·dated-month spread, target 6 in-window months) · pipeline passage 0.10 (extracted + ≥1 done entity mission). Hard gates then cap the total: no external source analyzed → ≤0.60; fewer than 3 of the 4 kind groups (actions=event, statements, information=role/affiliation/other, rumors) → ≤0.75; no completed entity mission → ≤0.80. Complete = ≥0.85 (_COMPLETE_THRESHOLD) — unreachable without going through the whole research pipeline. All weights/targets are named constants at the top of the module.

CLI

uv run cast-manager run [--batch 50] [--all] [--no-llm]
uv run cast-manager enrich [--limit 200]     # link Wikidata/Wikipedia (Gatekeeper)
uv run cast-manager analyze [--limit 50] [--no-llm]   # mine claims + article (Gatekeeper, Gemma)
uv run cast-manager politics [--limit 200]
uv run cast-manager score                     # bulk re-score under the current constants
uv run cast-manager status

Calibration: cached scores go stale whenever the metric's constants change — cast-manager score (or make cast-score) recomputes every character, persists fresh breakdowns and re-evaluates needs_research (deflated characters re-enter the queue). It runs at the end of make pipeline-characters. The admin sidebar shows the score distribution histogram and per-gate counts to judge whether the weights/targets need tuning against real data.

Under make pipeline the run records a cast_manager stage against the active run_id, and stamps newly-added characters with that run id (for the Results page). See run tracking.
