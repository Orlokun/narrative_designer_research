Propositor RE-1 Real

The Research Engine's mission generator. It scores every cell of the 16×13×48 matrix by coverage gap × thematic relevance × genre plausibility and emits ranked search missions for the Archivero — plus entity-driven missions for characters the Cast Manager flags as needing research.

Entry point: research_engine/propositor/__init__.py → main() · CLI: propositor run / status

What it does

  • Reads the 3D coverage table and ranks all 9,984 (theme, genre, month) cells: priority = (1 − score) × category_weight × genre_plausibility (+ critical-month boost). Plausibility priors from lib/genres.py keep structurally-empty pairings (Deporte × Cable diplomático) at the bottom without hard-excluding them.
  • Boosts priority for _CRITICAL_MONTHS (e.g. 1972-10 paro de camioneros, 1973-09 coup).
  • Builds queries genre-first: genre term + theme term, theme term, and a month-specific genre query (unique API results per cell).
  • Routes sources genre-first (the genre's natural connectors), topped up from the category source tier, capped at 6 per mission.
  • Optionally reformulates queries with Ollama (Gemma) for period-appropriate vocabulary; --no-llm skips this.
  • Polls the Cast Manager's needs_research character queue and mints entity missions ("research that person") — see below.

Gap missions carry their genre_id (legacy pre-genre missions have NULL → they block only the genre-0 cell, never a real genre cell). Duplicate cleanup keys gap missions by (category, genre, month).

Entity-driven missions (Cast Manager wiring)

After the gap pass, each cycle calls fetch_characters_needing_research() (from pipeline.cast_manager) and turns flagged characters into missions with kind = 'entity' and character_id set (build_entity_missions(); ids are prefixed e-). Details:

  • Priority = entity_priority(mentions, completeness): grows with mention count (saturating at 5), shrinks with the character's existing completeness score — comparable to gap priorities (0 to 1).
  • Queries are deterministic and seeded on what the cast already knows (entity_queries(name, aliases, salient_fact)): the exact quoted name + period, a query sharpened by the character's affiliation/role (e.g. "Donald Kendall" president of Pepsi-Cola), and a distinct alias to broaden recall — pulled from the research queue (fetch_characters_needing_research returns aliases + the top affiliation fact). No LLM reformulation, since names are exact-match terms.
  • Nominal cell. Entity missions carry a nominal (category 1, 1970-11) to satisfy the missions schema, but the Archivero skips the coverage-matrix update for kind='entity', so the matrix is never distorted, and entity missions never block gap generation for their nominal cell.
  • Queue semantics. Minting (or finding an existing entity mission) clears the character's needs_research flag; characters beyond --entity-limit (default 20, 0 disables) stay flagged for the next cycle. Duplicate cleanup treats entity missions per character_id, not per cell.
  • Focus modes (F3). --focus mixed (default: gaps + entities, unchanged behaviour) · --focus cells (gap missions only; the research queue stays flagged) · --focus characters (entity missions ONLY, and the queue is reordered least-complete-first via order_by_need() instead of most-mentioned-first — the make pipeline-characters mode, trigger characters in run tracking).
  • Location missions. In mixed mode the Propositor also polls the Location Manager's queue and mints kind='location' missions (--location-limit, default 10, 0 disables; ids prefixed l-) with kind-flavoured queries (location_queries: a building searches arquitectura planos, a factory industria producción). Same nominal cell, same attempt/cooldown bounds; duplicate cleanup keys them per location_id.
  • Closed research loop. Each minted mission is one attempt — the Propositor bumps the character's research_attempts and stamps last_research_at. Only in-flight (pending/running) entity missions suppress re-minting, and entity duplicate-cleanup keeps the newest mission, so a fresh attempt supersedes the character's earlier done mission. The Cast Manager re-flags a still-thin character after its cooldown (should_research: completeness < 0.85 under the strict metric, max 5 attempts, 3-day cooldown), so the loop iterates and then rests. Documents a mission harvests are attributed back to the seed via documents.seed_character_id.

Query uniqueness

Every mission includes a month-specific third query ("{category} Chile {month_iso}") so OpenAlex/CrossRef return different results per month. Without it, all non-critical months of a category produce duplicates and get marked failed.

Mission lifecycle

Missions move pending → running → done | failed. Network-only failures reset to pending (retry next cycle). _cleanup_duplicates() runs at cycle start. Full failure semantics on the Architecture page.

Common invocations

make propositor                                   # run --limit 100
uv run propositor status
uv run propositor run --retry-failed --no-llm --limit 100   # retry failed missions
uv run propositor run --entity-limit 0                      # gap missions only
uv run propositor run --focus characters --entity-limit 30  # entity only, thinnest first
uv run propositor run --focus cells                         # gap only, queue untouched
